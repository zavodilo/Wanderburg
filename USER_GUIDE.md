## 1. Что такое PlayArcEngine

PlayArcEngine — лёгкий web-first набор для создания 3D-игр, построенный поверх PlayCanvas Engine 2. Основные части проекта:

| Часть | Назначение | Что пользователь меняет |
| --- | --- | --- |
| PlayCanvas Engine 2 | 3D-рендеринг, камера, сущности, ассеты | Обычно не меняется |
| PlayArcEngine runtime | World3D, terrain, camera, model/UI helpers | Игра и конфигурация |
| Web Editor | Сцена, inspector, gizmo, история, сохранение | Визуальная настройка |
| Game.js | Игровая логика | Правила игры |
| Objects.js | Объекты сцены | Пропсы и объекты |
| UILayout.js | Позиции и свойства UI | Интерфейс |
| Constants.js | Параметры проекта | Общие настройки |
| tests / tools / claude | Проверка и AI workflow | При расширении проекта |

Главный принцип: **сцена и настройки остаются обычными файлами проекта**, а редактор помогает менять их визуально.

## 2. Что нужно для работы

- Git — чтобы получить исходники репозитория.- Современный браузер с поддержкой WebGL2.- Node.js — нужен инструментам проверки и сборки репозитория.- На Windows для первого запуска удобнее использовать готовые BAT-команды проекта.

> **Важно:** runtime игры не должен требовать `npm install`, но инструменты разработки могут использовать Node.js.

## 3. Первый запуск за 5 минут

Начните со свежего клона репозитория:

```bash
git clone https://github.com/zavodilo/PlayArcEngine.git
cd PlayArcEngine
```

Дальше:

1. Запустите `run.bat`.
2. Откройте адрес, который напечатает локальный сервер.
3. После загрузки вы увидите 3D-сцену и UI проекта.
4. Для визуальной работы со сценой запустите `editor.bat`.
5. В редакторе меняйте объекты и параметры, сохраняйте их и снова открывайте runtime.

> **Не рекомендуется:** открывать основной `index.html` как `file://`, если проекту нужен локальный сервер.

## 4. Как пользоваться веб-редактором

Редактор PlayArcEngine предназначен не только для художника: его задача — превращать сцену в редактируемые исходные файлы. Изменения можно одновременно видеть в 3D и хранить в Git.

### 4.1. Основные области редактора

| Инструмент | Что делает |
| --- | --- |
| Viewport | Показывает 3D-сцену и текущую камеру. |
| Objects | Список объектов сцены; выбор объекта открывает его свойства. |
| Inspector | Изменение имени, модели, позиции, поворота, масштаба и других свойств. |
| Gizmo | Перемещение, вращение и масштабирование выбранного объекта. |
| History | Отмена и повтор серии изменений. |
| Camera controls | Переключение между свободной и игровой камерой. |
| Save | Записывает изменения в файлы проекта, а не в бинарную сцену. |

### 4.2. Базовый сценарий: поставить объект

1. Откройте Editor.
2. Выберите объект в списке Objects.
3. Найдите его в Inspector.
4. Измените Position или перетащите gizmo в Viewport.
5. При необходимости измените Rotation и Scale.
6. Сохраните сцену.
7. Перезапустите игру и убедитесь, что объект появился там же.

По умолчанию игровой слой использует карту координат `(x, y)`, а PlayArcEngine адаптирует её к координатам PlayCanvas. Пользователю обычно не нужно вручную учитывать это зеркалирование.

### 4.3. Как не сломать сцену

- Не редактируйте одновременно один и тот же объект через editor и вручную в `Objects.js`.
- После большого набора изменений сохраните сцену и сразу запустите проверку.
- Если объект визуально пропал, сначала проверьте `Position`, `Scale` и активную камеру.
- Если исчезли все объекты, проверьте, не был ли заменён целиком `Objects.js`.

## 5. Как устроена сцена пользователя

Важные данные сцены хранятся в обычных JavaScript-файлах. Это упрощает Git, просмотр изменений и работу AI-агентов.

| Файл | Что хранит | Когда менять |
| --- | --- | --- |
| `js/Objects.js` | Описание размещённых объектов сцены | Пропсы, здания, декоративные объекты |
| `js/UILayout.js` | Положение и свойства HUD/UI | Размер, позиция, текст, панели, кнопки |
| `js/Constants.js` | Общие числовые и визуальные константы | Камера, свет, стиль, лимиты |
| `js/Game.js` | Игровую логику | Поведение игрока, NPC, оружия и системы игры |

### 5.1. Пример объекта

```js
{
  name: "House",
  model: "assets/models/house.glb",
  x: 420,
  y: 680,
  h: 0,
  rot: [0, 1.2, 0],
  scale: [1, 1, 1]
}
```

Редактор использует эту модель как источник истины для объекта. Поэтому изменения gizmo должны приводить к изменению этих значений, а не к созданию отдельного скрытого состояния.

## 6. Ассеты и 3D-модели

Для игровых моделей PlayArcEngine ориентируется на web-friendly asset pipeline PlayCanvas. Практический базовый формат — GLB/glTF.

> **Рекомендация:** для новой игры заранее приведите модели к GLB и проверьте их в браузере до массовой расстановки на карте.

### 6.1. Рекомендуемый workflow ассета

1. Подготовьте модель в Blender или другом DCC.
2. Экспортируйте GLB.
3. Положите файл в каталог `assets/` проекта.
4. Загрузите или выберите его через editor/import workflow репозитория.
5. Проверьте масштаб, pivot, ориентацию и материалы.
6. Разместите модель через Objects/editor.
7. Запустите игру и проверку.

### 6.2. Если модель не видна

- Проверьте путь к файлу и расширение.
- Проверьте, что файл доступен локальному web-server.
- Проверьте `Scale`: слишком маленькая модель визуально выглядит как отсутствующая.
- Проверьте Pivot/Origin модели.
- Откройте browser console и повторите запуск.

### 6.3. Текстуры и производительность

- Держите текстуры разумного разрешения; не используйте 4K/8K без необходимости.
- Объединяйте материалы и уменьшайте количество draw calls там, где это оправдано.
- Повторяющиеся пропсы выгодно переиспользовать как один asset.
- Проверяйте игру именно на целевом устройстве, а не только на мощном desktop.

## 7. Как редактировать интерфейс

`UILayout.js` — декларативное описание UI. Пользователь может сначала настроить расположение визуально, а затем при необходимости точечно изменить данные вручную или через AI.

```js
const UI_LAYOUT = [
  {
    id: "hp",
    kind: "bar",
    anchor: "top-right",
    x: 30,
    y: 30,
    w: 236,
    h: 12,
    value: 1,
    color: "#61e0b4"
  }
];
```

| Свойство | Смысл |
| --- | --- |
| `id` | Уникальное имя, по которому код получает элемент. |
| `kind` | Тип элемента: `text`, `panel`, `bar`, `button` и др. |
| `anchor` | Точка привязки к viewport. |
| `x / y` | Смещение от anchor. |
| `w / h` | Размер элемента. |
| `text` | Текст для `text`/`button`. |
| `value` | Текущее значение для `bar`. |
| `color / fill / border` | Визуальные параметры. |
| `visible` | Видимость элемента. |

## 8. Как писать игру поверх PlayArcEngine

Обычно пользователь не меняет `World3D`. Для поведения игры основная точка входа — `Game.js`.

| Задача | Лучшее место |
| --- | --- |
| Положение статического объекта | `Objects.js` / Editor |
| Вид HUD | `UILayout.js` / Editor |
| Геймплей | `Game.js` |
| Общие настройки | `Constants.js` |
| Рендеринг и backend | `World3D.js` — менять только при развитии движка |

### 8.1. Базовый игровой цикл

```js
class Game {
  constructor(app) {
    this.app = app;
    // state
  }

  update(dt) {
    // input
    // gameplay
    // enemies
    // UI
  }
}
```

В штатном запуске runtime вызывает `update(dt)` каждый кадр, затем система рендеринга рисует актуальное состояние сцены.

## 9. Использование AI-агентов

PlayArcEngine организован так, чтобы AI-агент мог читать инструкции проекта, изменять текстовые файлы и после этого запускать проверки. В репозитории есть `CLAUDE.md` и набор skills; дорожная карта дополнительно предусматривает semantic API, manifest сцены и headless/visual verification.

> **Рекомендуемый AI workflow:** сначала прочитать правила проекта и нужный skill, затем изменить минимальный набор файлов, затем проверить результат.

### 9.1. Практический запрос агенту

```text
Создай top-down survival на одной карте:
- игрок с WASD;
- прицеливание мышью;
- автоматический огонь;
- 3 типа врагов;
- XP и уровни;
- HUD для HP/XP/wave;
- не добавляй новые runtime зависимости;
- после изменений запусти check и исправь ошибки.
```

Хороший запрос содержит не только художественную задачу, но и ограничения проекта: какие файлы можно менять, какие проверки выполнить и что считать готовым.

### 9.2. Что агенту лучше НЕ поручать

- Не просите AI менять низкоуровневый PlayCanvas renderer без необходимости.
- Не просите заменять scene format на бинарный без причины.
- Не смешивайте большую реорганизацию движка с фичей игры в одном PR.
- Не принимайте результат только по тому, что JavaScript синтаксически корректен: нужен runtime/headless/visual smoke.

## 10. Проверка, сборка и диагностика

В проекте есть `tools/check.mjs`, тесты и JSDoc/TypeScript-проверка. Это должно быть частью обычного рабочего цикла.

```bash
node tools/check.mjs
```

| Проверка | Что ищет |
| --- | --- |
| Type/JSDoc check | Несогласованные типы и сигнатуры. |
| Node tests | Регрессии в чистой логике и tooling. |
| Build checks | Проблемы сборки, ресурсов и структуры. |
| Debug3D / headless | Проблемы запуска сцены и runtime. |
| Browser console | Ошибки загрузки ассетов, API и UI. |

### 10.1. Минимальный цикл перед commit

1. Сохраните изменения editor/кода.
2. Запустите `node tools/check.mjs`.
3. Откройте runtime и проверьте ключевой сценарий руками.
4. При 3D-изменениях посмотрите console.
5. Закоммитьте только связанный набор изменений.

> Для релизного workflow ориентируйтесь на критерии текущего `ROADMAP.md`: зелёные типы/тесты, headless-рендер без ошибок и, по мере готовности, visual smoke проверки.

## 14. Частые проблемы

| Симптом | Что проверить первым |
| --- | --- |
| Чёрный экран | WebGL2, browser console, запущен ли локальный server. |
| Loading не заканчивается | Не открыт ли проект через `file://`; не блокируется ли asset/server request. |
| PlayCanvas не загрузился | Проверьте локальный `libs/playcanvas.min.js` и Network tab. |
| Модель не видна | Путь, GLB, scale, camera, asset request. |
| Gizmo двигает не туда | Выбран ли правильный объект и не смешиваются ли map/renderer coordinates. |
| UI не меняется | Совпадает ли `id` элемента с `UI.get(id)`. |
| Игра падает после AI-правки | Запустите `tools/check.mjs` и откройте browser console. |

## Визуальные профили и варианты (Profile / Variant)

Игра описывается один раз (`js/GameSpec.js`) и может выглядеть пятью способами: **2D**,
**2.5D**, **Isometric 3D**, **Low-poly 3D**, **Full 3D**. Профиль — тип представления
(камера/проекция, спрайты или модели, свет, бюджет); вариант — конкретная настройка этого
проекта (`presentation/variants/<id>.json`). Варианты делят одну модель игры: id сущностей,
мир, правила и сохранения одинаковы во всех.

Запуск:

```
node tools/arc.mjs run --all                     # пять вкладок: по одной на вариант
node tools/arc.mjs run --variant <id>            # один вариант
открыть /?project=<id>&variant=<id> в браузере   # то же самое вручную
```

В игре клавиша **V** (или кнопка «Visual variant…») переключает вариант на лету: та же игра
перерисовывается спрайтами, биллбордами или моделями — gameplay не меняется. Сохранение,
сделанное в 2D, читается в Full 3D: в файле сохранения нет профиля.

Редактор, вкладка **Profile**: строки project / profile / variant, список возможностей
профиля, бюджет, отсутствующие ассеты и фолбэки, журнал миграций; селектор варианта в тулбаре
переключает предпросмотр во view без записи файлов; «Preview migration» показывает план
(сколько сущностей, замен, отсутствующих ассетов, изменено ли что-то в gameplay — всегда 0),
«Apply migration» создаёт/обновляет целевой вариант и сохраняет его через сервер редактора,
«Create all variants» создаёт по варианту на профиль.

Конверсия из консоли:

```
node tools/arc.mjs variant plan --from 2d --to full3d          # план без изменений
node tools/arc.mjs variant convert --source <вариант> --profile full3d \
       [--dry-run] [--write-placeholders]                      # применить (+ PNG-заглушки
node tools/arc.mjs variant compare <a> <b>                     # чем различаются варианты
node tools/arc.mjs validate --all                              # проверка всех вариантов
```

Недостающие ассеты не ломают игру: цепочка fallback доводит до примитива или генерируемой
заглушки (карточка со штриховкой и именем роли), а `--write-placeholders` кладёт заглушки
файлами в `assets/visual/<профиль>/` — заменить их настоящим артом можно позже.
